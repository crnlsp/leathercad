# The 1.7 UX audit — baseline findings and what each slice fixes (U.21 – U.26)

**Status:** complete for Linux (U.21, 2026-11-15), for the 1.7 plan
([`2026-11-03-release-1.7.md`](../plans/2026-11-03-release-1.7.md)). The first pass saw thirteen
screens; the second inspected every screen it had left *not inspected* or *from code only*, and
added X19–X39. Windows and macOS wait for R17, and Orca's own speech for a machine that has it
(§1.2).

## 1. What was inspected, and how

### 1.1 The second pass (U.21)

The built app at develop 4e34d11, on Linux (CachyOS, Wayland), 2026-11-15, driven the same way: a
scratch Playwright script, its own configuration and state folders, projects opened from copies of
`fixtures/projects/` (renaming a project renames its file), and a stand-in for the CUPS client on
`PATH` so that Print and *Print calibration page* reached no real printer. Sixty-eight captures,
each with the accessibility tree of what it showed:

- **Sizes.** 1440 × 900 CSS px at display ratio 1; 1100 × 720 at 2× and 1280 × 800 at 125 % and
  150 % (`--force-device-scale-factor`, Chromium's stand-in for OS scaling); the minimum window,
  860 × 600, at each.
- **Keyboard only.** From the start screen: Tab to *New project from template*, Enter, type in the
  search, Enter on the card holder; Tab through the window; on the board Ctrl+A and an arrow
  nudge; Ctrl+S; Ctrl+E to a PDF; Ctrl+P, Tab to *Print*, Enter. A blank project drawn with the keys
  alone (R, 300 Tab 250 Enter). Every dialog's Tab order and first focus.
- **Screen reader.** The accessibility tree of every capture, and the window's live regions read
  after a save, a problem, a selection and a nudge — what Orca is given through AT-SPI.
- **Workflows.** A card holder from blank (two pieces, each through the selection bar's next
  steps); the bifold from its template, exported and printed; a five-piece bag drawn as *Stitch
  line + allowance*, then Sheets and Print Preview.

### 1.2 What was not done

- **Orca was not run.** It is not installed on the inspection machine, and installing it needs
  the administrator. What it would be given was read instead: the accessibility tree and the live
  regions, which is where X21–X23 come from. Listening to Orca announce a save, a problem and a
  selection is still owed, and is repeated on the release candidate (plan §7).
- **Windows and macOS** were not inspected: no such machine here. Nothing in §2 depends on the
  platform except the font, the window frame and the print path; R17 checks them.
- **Import of a real template file** was inspected with a project file (`.lcp`), the one kind the
  dialog offers; a template exported from another machine was not.

### 1.3 The first pass

The built app at develop 7a69dc9 (the 1.6.0 code), on Linux (CachyOS, Wayland), at 1440 × 900 CSS
px, display ratio 1, the one theme, in English, driven by a scratch Playwright script with its own
configuration and state folders, 2026-11-03. Thirteen screens were captured; the code was read for
the rest — the rows §1.1 now marks seen.

**There is no light theme.** The window is one design: a dark shell around a light, paper-like
board — "light card in a dark shell", decided in the
[2026-09-17 visual-language audit](2026-09-17-ui-ux-audit-and-visual-language.md) §5.4. A light
*shell* would be a new feature, not a check: every token in `packages/render/src/theme/` defined
twice, contrast audited twice, the pixel baselines doubled. Whether 1.7 adds one is open (plan §3,
D11, 2026-11-03), decided during the release by how the work is going; until then it is not a 1.7
test.

## 3. Screen by screen — what each slice does

**Start screen (U.23).** Templates as cards with the previews the picker already draws, the blank
project first and primary (Ctrl+N on its card); *Open…* beside; recent projects with dates and
pins as today. Not a wizard (*Not planned*). X10, X20.

**Project tabs (U.24a).** X27, X28. Rename, the tab menu, drag, Ctrl+Shift+Page Down, middle-click,
reopen and the outside-change bar work as built (X39).

**Template picker and management (U.24b).** X11, X29, X31; lighter controls with few items. The
empty *Mine* state explains how to make one (X39).

**Guides and Arrange (U.24c).** X7, X8, X9.

**Parts tree, Properties, selection bar (U.24d).** Seam lines (9.6b), pocket readings (9.14a) and
the production summary (9.12) land here; check their density at 1100 px and the minimum window.
X32, X33, X35, X40.

**Problems (U.24e).** With 9.15's explanations: each row's *why* and *what to do* readable at the
panel's width; *go to* on every row; keyboard next and previous problem. X22, X23.

**Export dialogs (U.24f).** Inspected: the two intents, the layers, the page size reported live, Tab
order (X39); nothing new to fix. Q43's overlap warning has landed.

**Print Preview, Sheets, calibration (U.24g).** X19, X24, X25, X36. A taped part, the corrected
caption and the guard's refusal ("almost certainly a print-settings problem") read as built.

**Save, recovery, warnings, success (U.24h).** The save notice, the recovery offer, the unsaved
dialogs, the outside-change bar, the update chip: one notice style, one tone per meaning. X26,
X30.

**The visual system (U.25).** Spacing, type, icon sizes and states from the theme tokens only (the
`styles.css` audit test holds that); hover, active, focus, disabled and locked states the same on
every control; contrast checked on every new surface; focus order and visible focus on every new
control; the minimum window; HiDPI at 2× and OS scaling at 125 % and 150 %. X19 (focus), X21,
X34, X37.

**Languages (U.26).** Every word added in 1.7 in `en.json` through `t()`; plurals by CLDR form; a
pseudo-locale (every string lengthened about 40 %, development builds only) run over the new
screens to find what overflows; review PR #87 (Russian) against ADR 0018 and preserve its
attribution. U.26 now also registers
Polish/German/Russian/French in production and permits missing translations with English fallback;
see the [translation guide](../../localization.md) and [verification record](../../localization-verification.md).
